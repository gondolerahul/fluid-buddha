# Install surfaces (M2-10)

Ways to put the FluidBuddha agent on a customer's site without editing HTML by hand.
Every one of them adds the same script from the FluidBuddha server:

```html
<script src="https://<server>/widget/loader.js" data-key="fbk_…" async></script>
```

`/widget/loader.js` ([`backend/app/routes/widget.py`](../backend/app/routes/widget.py))
adds the widget bundle (from `WIDGET_SDK_BASE`) with the same settings and points it
back at the server it came from. So an install needs only the server and the widget
key, and everything else — tier, design, colour, greeting, languages, knowledge,
triggers, A/B tests — comes from the console without touching the site again.

Plugins take both as one **install code**, `https://fbk_…@<server>`, shown per
website in the console's Install tab.

| Surface | Folder | How it's installed | Tests |
|---|---|---|---|
| WordPress plugin | [`wordpress/`](wordpress) | Settings → FluidBuddha → paste the install code | `php tests/test-functions.php`, `php -l` |
| Shopify app (theme app extension) | [`shopify/`](shopify) | Theme editor → App embeds → FluidBuddha agent | `npm test` (renders the Liquid) |
| Google Tag Manager | [`gtm/`](gtm) | Import the server-generated template, or a Custom HTML tag | template tests in GTM; backend `tests/test_install.py` |
| Webflow | [`webflow/`](webflow) | Site settings → Custom code → Footer | — (guide) |
| Framer | [`framer/`](framer) | Code component, or custom code | typechecked with the JS packages |
| React — `@fluidbuddha/react` | [`js/packages/react`](js/packages/react) | `<FluidBuddha installCode="…" />` | `npm test` in `js/` |
| Vue — `@fluidbuddha/vue` | [`js/packages/vue`](js/packages/vue) | `<FluidBuddha install-code="…" />` | `npm test` in `js/` |
| Composed pages — `@fluidbuddha/next` | [`js/packages/next`](js/packages/next) | `createPageHandler(…)` in a catch-all Route Handler, or `<ComposedPage>` (Phase 2) | `npm test` in `js/` |
| Page components — `@fluidbuddha/components` | [`js/packages/components`](js/packages/components) | `defineFbComponent(…)` + `npx fb-manifest` → console Components tab (P0-8) | `npm test` in `js/` |

The JS tests also run the backend's real loader script in jsdom.

## Publishing (needs your accounts)

- **npm:** `cd js && npm run build`, then `npm publish --access public` in each package
  (needs the `@fluidbuddha` npm org).
- **WordPress.org:** zip `wordpress/fluidbuddha/` and submit it.
- **Shopify:** `shopify app deploy` from `shopify/` with a Partner account; the App Store
  listing needs an app URL and privacy policy.
- **GTM Community Template Gallery:** a public repo with the template generated by the
  production server.
- **Webflow / Framer:** guides only; a Webflow App or Framer Marketplace listing is optional.
